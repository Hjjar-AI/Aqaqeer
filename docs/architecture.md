# Architecture

Implemented mechanisms live here; [requirements](requirements.md) owns product/acceptance rules, [validation](validation.md) executed evidence and [plan](plan.md) remaining work. Source descriptions do not establish runtime acceptance.

## Layers and storage

One Kotlin Android module uses Compose/Material 3, immutable `AppUiState`, Hilt ViewModels/repositories and Room/SQLCipher. `CatalogRepository` initializes on IO, observes table invalidations and seeds in an installation-marker-guarded transaction. Standard begins unconfigured; only `src/demo` supplies 40 [psychiatry/supportive-care sample records](demo-data.md), two fictional sections/status/expiry values and a random non-authorizing verifier, in separate debug package/storage. The demo launcher label is explicit; demo release is disabled. Demo seed version 3 can refresh the recognized prior demo or an empty demo installation in that same transaction, preserving device identity and keys and refusing unexpected pharmacy/authorization/work/history/restore/remote state. Standard’s refresh hook does nothing; DAO marker updates change no schema or migration.

A random 32-byte database key is wrapped by Android Keystore AES-256-GCM. SecureStore uses fresh nonces, package/namespace/entry AAD, AtomicFile, bounded reads and `noBackupFilesDir` without user-authentication gates. Missing wrappers/keys enter recovery without replacement or wipe; manifest/legacy/cloud-transfer backup excludes app data. The preserving SQLCipher bridge supplies its own native corruption handler and refuses `onBeforeDelete`, rather than SQLCipher 4.19.1 SupportHelper's deleting default; Room callbacks remain delegated.

The fresh Room version is 1; shared/file payloads use their initial contract without price/currency or historical development upgrade registrations. Shared records and local identity/history/base/pending/attempt/compatibility metadata follow [the entity contract](requirements.md#7-data-model-and-invariants). UUIDs, Instant/LocalDate converters, foreign keys/unique availability pairs and RESTRICT taxonomy deletion enforce integrity. Protected seed IDs end in `001` (Uncategorized), `100` (starter section) and `201`–`20f` (15 forms) within `00000000-0000-4000-8000-…`; only Uncategorized/Other are protected taxonomy rows. `CatalogSeeds.defaultMedicationFormId` selects existing Tablets, otherwise Other; editor and CSV creates share it while updates/restored drafts retain choices. Creation writes explicit AVAILABLE pairs for existing sections atomically; later-section/missing legacy pairs remain UNKNOWN.

`DatabaseFactory` owns one shared connection with idempotent leases. Main repositories release leases; reset blocks acquisition, drains users and closes/reopens after cancelling the old observer. Staging uses separately owned one-shot connections closed before deletion. Restore/leave replace active rows transactionally rather than deleting the main database.

`ProtectedReadCache` caches decoded maintenance/compatibility metadata by secure-store namespace/entry under the shared read/write lock. Every write attempt invalidates its entry, even on failure; recovery clears metadata caches. Credentials/DB keys are excluded. Catalog observation reuses validated content on metadata-only invalidations, rereads after activation/leave and deduplicates equal states. Reader fallback decoding changes only with publication identity. Confirmed-state writers atomically persist exact ISO Instant publication text; restore validates it against the payload. The generated version-1 export has dated delivery evidence.

## Import and protected connection state

SAF OpenDocument accepts broad MIME labels; authenticated envelope/domain/payload validation decides acceptance. ACTION_VIEW accepts content URIs matching connection MIME or `.aqz` JSON/octet-stream paths; opaque providers use the picker. File/http URIs are rejected, no persistable grant is taken and the memory-only URI is cleared from the intent to prevent recreation replay. External originals remain untouched; process death can require reselection.

The import repository checks unconfigured/non-demo/non-recovery eligibility before decoding and staging. Configured devices use explicit same-pharmacy maintenance. One pending candidate is allowed, replaced only after confirmed discard. `pending-connection`/`active-connection` are separate from `database-key`; the versioned binary record carries magic, staging UUID, pharmacy/issuer metadata, token/group/key version and snapshot key. Modified-UTF text is capped at 8,192 UTF-16 units, record at 256 KiB, SecureStore at 1 MiB. Removal checks staging identity and writes an authenticated empty marker; corrupt/unsupported records fail closed.

Password UI uses unsaved `remember`; handoff clears text and transferred CharArrays are zeroed after completion/cancellation. ViewModel can retain URI/ongoing work across rotation, not unsubmitted passwords. UI exposes metadata only, never raw provider/crypto messages or credential URLs. Owned staging/key arrays are cleaned; immutable/provider copies cannot be claimed erased.

Load/stage/discard/verify/activate serialize in the repository; envelope/model work shares a process-wide mutex. Abandoned stages are cleaned on IO without delaying splash. Cancellation after an atomic write reloads actual protected state instead of claiming rollback; committed pending state needs explicit removal. Blocking providers/crypto may delay cancellation.

## Verification, requirements and activation

Pending verification checks staging ID, authenticates a fresh read and retains the candidate on failure/success. Its memory-only summary labels supported counts, publication identity/time, actual observation time and requirements (UTC before configuration); it does not authorize activation. Stable Arabic error categories replace raw transport/provider messages.

`SnapshotRequirementsStore` stores maximum authenticated schema/minVersionCode per pharmacy in protected 12-byte magic/schema/minimum-app records. Invalid authentication/pharmacy/caption/pin observations create no requirement. Records survive discard/re-import/restart, cannot be lowered or overwrite corruption, and finish persistence in a short noncancellable step; failed persistence returns recovery. Unsupported payloads never apply. Startup, refresh and commands enforce [compatibility restrictions](requirements.md#10-history-import-exports-updates), including retained restrictions on restore and authorized compatible backup export.

Activation downloads/authenticates again, checks candidate/requirements, writes protected active credentials then commits Room. The transaction accepts only the unconfigured seed with no pending/history/attempt/tombstone/base work; stores supported wire JSON plus publication/document/read metadata, retains installation identity, forces reader/shared lifecycle and imports no earlier history. Network remains cancellable; commit/cleanup complete noncancellably. Before commit, pending remains retryable; after commit, startup recognizes matching staging ID/pharmacy and finishes cleanup without network. Discard removes matching precommit credentials. Multi-instance invalidation updates observers; protected failures preserve data.

## Telegram reads and refresh

`SnapshotReadTransport` separates bot/pin/owned-download interfaces from official-host HTTPS getMe/getChat/getFile and credential-free fakes. It checks private group/supergroup identity, no public username, matching chat and a bot-owned non-forwarded document. Wire/header/caption/path/TLS/time/resource constraints remain in [readers](crypto/READERS.md).

Always-download reads authenticate pharmacy/key, compare caption/header and recheck full group/message/file/fileUnique/publication identity. Activation/publication/recovery always use this path. Refresh alone may skip download after strict reparsing of protected confirmed JSON and complete identity/pharmacy/key/compatibility equality; it still verifies bot and pin twice. Invalid cache fails closed; retained unsupported requirements force a fresh observation. This is no remote lock.

An app-owned Deferred coalesces foreground/pull/retry requests; a cancelled waiter does not cancel shared work. Navigation alone creates no request, local startup never waits for network and demo/unconfigured/draft/recovery paths create no foreground traffic. Completion/failure permits retry; no permanent background worker exists.

Same-publication observations require semantic catalog/metadata equality independent of array order. Only a direct next revision with matching parent applies automatically. ID reuse, gaps, divergence/regression, conflicts or uncertain attempts retain candidates for review. Application rechecks active identity, base metadata and visible catalog, then commits catalog/tombstones/base/document/read metadata and observed history atomically. Only applied or unchanged accepted snapshots update the observed PIN and revoke mismatched authorization; rejected recovery candidates preserve authorization and device identity. Failures preserve usable data and times. Encrypted input is capped at 10 MiB, normalized JSON at 32 MiB; workspace checks precede history maps and never truncate.

Observed field JSON values carry revision/observation time, not invented original authorship. A separate publication event carries authenticated publisher/time. Recovery candidates use encrypted history `entityType=snapshot`, `field=recoveryCandidate`, oldValue=current base ID, newValue=complete supported wire JSON, deduplicated by base/candidate-derived UUID. They neither become pending attempts nor replace the base; backups retain them. Large history/snapshot/attempt values use bounded cursor/byte reads rather than assumed small rows.

## Creation, edits and publication

Current `local_control` stores lifecycle, PIN failure/observed/authorized verifier identities, reconnect intent, restore/reminder flags and resumable leave state. Protected `pin-delay` stores the shared promotion/current-PIN-change failure count, boot count and elapsed-time deadline; wall-clock changes do not bypass it. Process restarts preserve it; a reboot conservatively restarts the outstanding delay. Successful verification resets it, confirmed leave clears it, and backups never export it. Legacy wall-clock retry values are no longer used. Creation atomically writes pharmacy/seeds/editor/admin authorization; normalized salted PBKDF2-HMAC-SHA256/200,000 PINs are not retained. Accepted creation resets validation and a PIN-input session key, clears transferred secrets and uses collected/synchronous busy guards; failures restore untouched empty PIN inputs, invalid submissions retain entered text. Leave persists intent before protected/local cleanup; startup resumes it.

Admin transactions commit guarded business changes, history and saved-base operations together. Repeated edits retain original bases; unpublished additions absorb later changes, return-to-base removes net work without deleting history, and in-flight IDs are never coalesced away. Pending replay follows SQLite insertion order. Readers project confirmed data; promotion uses the latest observed verifier and durable increasing failure delays.

Separate setup/write adapters check official host, identity/group/admin permissions and setup-only random challenge discovery, refusing webhooks; manual group ID is validated and confirmed before protected setup credentials/key are saved. Writers use SecureRandom/domain-separated bounded encryption. Issuance requires verified shared state and SAF.

Publication serializes with setup/leave and persists candidate/base JSON, fixed operation IDs, upload IDs and phase before mutation. Shared state with no pending operations or uncertain attempt clears completed reconnect intent and returns without transport activity or claiming a verified publication. Retry cooldowns use elapsed time and expose remaining seconds as retryable status. Bootstrap uses revision 1/null parent/base 0 and refuses an existing pin; normal publication fetches/merges/rechecks the pin before media replacement, then always authenticates read-back. Pending-operation removal and history acknowledgment/retargeting chunk ID lists at 500 inside their transactions. Only exact verified candidates acknowledge captured work; later edits remain pending. Lost responses reconcile live identity; divergence/missing pins/ambiguous outcomes retain candidates for explicit review. Telegram offers no cross-device conditional write.

Merge compares business values, including deletion/dependent/reference/restoration conflicts. Normalized taxonomy-name collisions require an explicit surviving-item choice or a local rename; rejected category/form references use their fallbacks and rejected section availability is removed, as explained in review. A combined section count outside 1–5 requires choosing the retained local or remote section membership, preserving merged fields on surviving IDs. Unrelated taxonomy changes survive. Deletions conservatively review any changed remote catalog, recompute fallback/cascades and bind choices to a remote digest. If no local change survives, retain remote derived attribution; otherwise select accepted changes by `(authoredAt, authorId, operationId)`, including derived reassignment. This ordering never resolves conflicting business values. Online saves wait for Publish; retained offline intent may trigger up to three foreground reconnect attempts, paused by review/authorization/compatibility. Startup alone does not publish online-saved work.

## Encrypted backup and restore

`BackupRepository`'s authorized internal database-open/output-stream seams retain normal injection and all security/transaction guards. Under the sharing mutex, an ordered versioned table allowlist is captured in one Room transaction. `BackupArchive` encodes nullable cells as bounded Base64 UTF-8 chunks, preserving insertion order and large bases/history; active identity/authorization/reminders are excluded.

`V1BackupEnvelope` keeps the pinned 64 MiB complete-envelope domain. Private plaintext staging is immediately protected in independently authenticated 64 KiB AES-GCM chunks with an ephemeral key; import rows use separate SQLCipher storage. Conservative headroom covers provider buffering; OOM recovery is not a strategy. IO is off-main, serialized with crypto and cancellable between chunks, including queued input ownership. Export authenticates/validates staged output through the same payload path before SAF writing. Startup/next operation removes abandoned owned stages.

Authenticated UTF-8/type/reference-valid input materializes before active changes. Bounded copies replace allowlisted rows transactionally while retaining installation identity/revoking authorization. A protected write-ahead credential journal activates only for a matching committed Room checkpoint, replayed idempotently at startup. Restore pause, connection confirmation/activation and reminder state are current initial-schema fields, not an upgrade recipe.

Restored shared state pauses ordinary refresh/reconnect/publication until explicit group confirmation and live reconciliation. Same-bot tokens are validated without replaying transport phases; observed live verifiers revoke mismatched authorization, survive reconciliation/replacement and remove restored PIN-change intentions. Uncertain candidates are authenticated as accepted or explicitly archived before rebasing. Reconciliation never publishes; normal publish rechecks live PIN/lineage. Draft restore resumes through local/setup actions.

Reminder baseline is first local authorization, last fully closed successful SAF export and dismissal. An existing admin missing a timestamp gets a baseline on observation. These local values are excluded from backups, retained on same-pharmacy restore and cleared on leave. Resource/device measurements and their limitations belong in validation.

## Credential maintenance and recovery

`MaintenanceCoordinator` uses IO and the sharing mutex. Its bounded versioned SecureStore journal holds operation/phase, credential references, publication identities and backup receipts; original/candidate/temporary credentials remain separate protected entries. Isolated SQLCipher staging retains source catalog, bases, pending/attempt rows and candidate JSON using bounded large-value readers.

Preparation persists pause before capturing/resuming its stable baseline. Domain/refresh/reconnect guards enforce the pause; cached view, authorized backup/history/help and explicit recovery remain available. Corrupt metadata does not replace keys or erase work. Leave clears owned unreadable journal/staging entries; restore clears local maintenance/PIN associations, never importing their authority.

Activation writes a UUID to the protected journal, commits catalog/base and a matching Room history event, then switches active credentials only after that event is found. Startup completes activation before normal reads; interrupted precommit work keeps the old connection. Completion/cancellation cleanup is resumable; history projections hide internal checkpoints.

Replacement authenticates a bounded same-pharmacy `.aqz`, verifies fresh supported data, then downloads again and compares frozen local state before activation. Bases/uncertain attempts survive; readers retain confirmed-only projection. Admin review authenticates live state, recognizes exact accepted candidates or archives uncertain candidates, then reuses normal merge/attribution. Invalid pending PIN intentions require explicit discard/new current-PIN authorization. Clearing pause does not schedule publication.

PIN changes bind current-PIN authorization, exact next verifier and operation ID in a protected local association. Only the installation's exact verified candidate/operation preserves its authorization, including lost-response reconciliation. Other verifier observations revoke it; no plaintext PIN or exported authorization is retained.

Maintenance backup reuses the mutex-owning export path; a receipt is issued only after complete validated writing/close. It binds operation/source publication/catalog/history/pending/attempt state. Source changes invalidate it before irreversible progress; old exports/reminders do not qualify. Unavailable-source relocation requires digest-bound retained-publication/time review first.

Rotation authenticates the actual same bot/group with the old key before staging a new key/version. Relocation confirms a permission-checked empty destination. Both persist candidate identity/transport progress before mutation, publish source revision+1 with source parent/based-on lineage, authenticate new-key read-back and use recoverable activation. Resumption inspects destination before rewriting; unexpected publications/keys pause review. Issuance stays paused until completion. Cancellation after possible remote effects requires usable-state reconciliation, never a claimed remote undo; distribution/source retirement remain manual. Shared UI exposes identity/status/conflict summaries, not secrets or journal internals.

Snackbar actions are route-scoped; View highlights visible results without resetting filters. Create can prefill the unmodified query; edit validates original target/pharmacy. ## Local history and pending presentation

`HistoryRepository` rechecks authorization/pharmacy/leave/restore activation per transaction. Destination-scoped flows cancel obsolete loads, clear replay on unsubscribe and reload on data/control changes; UI rechecks current scope. Read-only SQL projections page 50 events plus one lookahead by effective edit/publication-or-observation time, descending ID ties, undated last. Inclusive pharmacy-date filters become `[start, next-day)` instants; undated events miss bounded ranges. Editor/medication filters include retained deleted names/IDs. Filters/page are memory-only and reset on leaving; restored medication routes retain ID scope.

Cards distinguish local edits, observed changes, publications, recovery candidates and restore reviews. SQL projections redact verifier/whole-pharmacy/snapshot values and bound ordinary display to 512 Unicode code points; full stored history remains in backup. Deleted items retain names or labeled bounded fallbacks, without edit actions. Publication attribution is not original field authorship; missing revision acknowledgement is not proof of pending work.

The Home banner counts net pending rows, remaining for retained zero-count attempts or active publication. Connection readiness is metadata-only; domain guards control Review/Publish, explain blocks and route failures/uncertainty to review. Readers do not receive admin pending controls.

## CSV import and reports

`CsvCodec` streams strict UTF-8/optional BOM with multiline/escaped quoting. Limits: 10 MiB input, 10,000 records, 64 KiB decoded-cell UTF-8 and 20 columns (11 canonical + five section + four result). Preflight needs 80 MiB workspace + 16 MiB reserve; low-memory suitability is unmeasured. Duplicate/unknown headers or malformed quoting fail before writes; section/width/field problems become row errors. Result metadata is ignored on re-import; record numbers are not physical multiline line numbers.

ViewModel memory retains original cells and pharmacy baseline across rotation, not process death. Rows begin unselected; duplicates require decisions, selected update IDs must be unique and optional clears are explicit. Taxonomy proposals use deterministic session IDs with consent. Header-based scientific-first columns accept earlier ordering; removed price/currency is not an accepted field.

`CsvImportRepository` reuses guarded row transactions in source order, rechecking identity/target/explicit availability bases/references/duplicates. Taxonomy/medication/availability/history/pending commit together; no-ops stay inert. Short noncancellable commits record results before the next cancellation point. Completed rows survive later failure/cancellation; unprocessed selections get retryable errors, skips stay skips. There is no persistent replay journal or online auto-publish; offline edits retain reconnect intent. Authorization/compatibility/pharmacy changes clear exchange state.

Result CSV preserves business columns plus rowNumber/outcome/warning/error, neutralizes formulas, bounds/pads malformed widths and retains extra cells in error text. Retry CSV preserves raw cells/diagnostics and may need width repair; templates/retry files differ from safe spreadsheet reports. Outputs use BOM, quoted cells and CRLF. Section-ID guidance stays outside template headers; zero selected valid rows may still produce reports.

Reports capture an immutable authorized source, defaulting to confirmed published data and requiring explicit draft inclusion without silent fallback. Presets/metadata/exclusions follow requirements; secrets/verifiers never export and insufficient workspace fails. `PdfReports` uses bundled fonts/StaticLayout/Canvas on A4, scientific-first identity, original emblem/gold rule, repeated metadata/page numbers, line-aware/chunked continuation and a 1,000-page fail-not-truncate cap. Full pharmacy names remain in the body when headers shorten. Render before opening SAF; all heavy work is off-main and success follows destination close. Cancellation/provider failures may leave external partial files. Actual synthetic-device/raster results and other-provider/human limits belong in validation.

## Dates, tips, and freshness

The civil Hijri converter uses integer arithmetic, epoch 622-07-19 = 1 Muharram 1 AH, alternating 30/29 months and leap years 2, 5, 7, 10, 13, 16, 18, 21, 24, 26, 29 in a 10,631-day/30-year cycle. Pre-epoch dates get an unavailable explanation; civil midnight differs from moon-sighting/sunset conventions. Local `secondaryHijri` defaults off and adds detail/history labels without changing Gregorian inputs/business rules/shared dates/exports; history instants first use pharmacy timezone.

Expiry uses pharmacy ZoneId and overflow-safe date differences, never availability mutation. Lifecycle clocks refresh on resume/midnight and check clock changes at most a minute apart without persistent background work. OUT location hints exclude current/inactive/LOW/UNKNOWN sections. Last successful read and authenticated publication are independent, never invented from startup/medication edits; Western-digit Gregorian instants use pharmacy time. Validated connectivity drives offline state; ≥24-hour read age drives amber, with never-refreshed and future instants handled separately.
