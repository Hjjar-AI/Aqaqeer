# Architecture

Implemented mechanisms live here; [requirements](requirements.md) owns product/acceptance rules, [validation](validation.md) executed evidence and [plan](plan.md) remaining work. Source descriptions do not establish runtime acceptance.

## Layers and storage

One Kotlin Android module uses Compose/Material 3, immutable `AppUiState`, Hilt ViewModels/repositories and Room/SQLCipher. `CatalogRepository` initializes on IO, observes table invalidations and seeds in an installation-marker-guarded transaction. Standard begins unconfigured; only `src/demo` supplies 40 [psychiatry/supportive-care sample records](demo-data.md), two fictional sections/status/expiry values and a random non-authorizing verifier, in separate debug package/storage. The demo launcher label is explicit; demo release is disabled.

Catalog reads reuse post-recovery control/authorization, pending count and protected connection metadata within each transaction. Unpublished medication markers use a distinct target-ID projection, excluding pending JSON payloads. Required recovery, integrity, confirmed-reader visibility and compatibility checks still precede Ready. Backup housekeeping and initial pending-connection discovery start independently after the first local catalog resolution; explicit file operations retain their own staging cleanup and locks. These changes remove source-level work/competition, without establishing a measured startup improvement.

The corrected demo catalog is initial seed revision 1: 40 medications and 80 explicit pairs using only AVAILABLE/LOW/OUT. DemoSession supplies the displayed process-local workspace from that seed, starting as Reader even when older installed demo rows exist. Settings toggles simulated Admin and offers confirmed reset; role changes preserve edits, reset regenerates samples/clears pending and History, and a new process returns to Reader. CatalogRepository observation is overlaid only for demo.

Local AdminRepository.edit closures reuse existing validators/stale-target/Undo semantics against synchronized in-memory state; real transaction guards remain unchanged. Net pending operations are derived against the initial catalog and History is projected with normal filters/pagination. No role/edit writes reach Room/DeviceIdentity/protected storage; standard-app authorization and persistence remain blocked. Demo navigation now admits the shared admin hub, CSV/report/file screens and simulated connection controls; real Telegram HTTP entry points reject demo builds.

`DemoSession.initial` is the last simulated publication, separate from the admin overlay. Publish replaces that base, acknowledges pending work, advances its revision/time and labels local history; refresh records a simulated read without removing edits. Reader presentation uses the published base. The in-memory connection/online controls and reconnect intent never call real transports. Setup uses fixed fake group metadata, while maintenance has a dedicated simulated connection/PIN/rotation screen. The Settings quick role switch remains demo-only.

`ReportRepository.source/capture` shares selection, dates, immutable snapshots and renderers across flavors. Demo captures/exports require simulated Admin and bind reports to a workspace generation. CSV shares its existing planner/guards/results/export logic; demo commits hold the workspace monitor and emit one complete chunk, retaining the old state on failure. Reset/restore invalidate prior generations, and reset clears exchange drafts. Standard continues using the existing Room transaction/edit path.

`DemoFiles` uses SAF and the existing connection/backup envelope crypto. Demo connections have schema 0 (rejected by production header validation), an explicit fake-token marker and fake group/key fields; only matching demo credentials can activate the sample connection. Demo backups have a required demo-only marker and catalog/confirmed-base/history payload. Export authenticates and decodes the complete encrypted output before writing to the provider; restore authenticates/validates before replacing the sample workspace, revoking Admin and pausing simulated publication for review. Pending work is rederived, while the current simulated PIN/connection remain local. Owned encrypted/protected temporary files are cleaned without touching installed DBs/keys. These flows do not model live reconciliation, durable crashes or actual token revocation/migration.

The existing guarded initializer preserves identity/keys and refuses unexpected pharmacy/authorization/work/history/restore/remote state; previously installed development data is not reset or converted, and higher stored seed revisions are preserved. Standard’s refresh hook does nothing; DAO marker updates change no schema or migration.

A random 32-byte database key is wrapped by Android Keystore AES-256-GCM. SecureStore uses fresh nonces, package/namespace/entry AAD, AtomicFile, bounded reads and `noBackupFilesDir` without user-authentication gates. Missing wrappers/keys enter recovery without replacement or wipe; manifest/legacy/cloud-transfer backup excludes app data. The preserving SQLCipher bridge supplies its own native corruption handler and refuses `onBeforeDelete`, rather than the upstream SupportHelper deleting default; Room callbacks remain delegated.

The fresh Room version is 1; shared/file payloads use their initial contract without price/currency or historical development upgrade registrations. Shared records and local identity/history/base/pending/attempt/compatibility metadata follow [the entity contract](requirements.md#7-data-model-and-invariants). UUIDs, Instant/LocalDate converters, foreign keys/unique availability pairs and RESTRICT taxonomy deletion enforce integrity. Protected seed IDs end in `001` (Uncategorized), `100` (starter section) and `201`–`20f` (15 forms) within `00000000-0000-4000-8000-…`; only Uncategorized/Other are protected taxonomy rows.

`CatalogSeeds.defaultMedicationFormId` selects existing Tablets, otherwise Other; editor and CSV creates share it while updates/restored drafts retain choices. Creation writes explicit AVAILABLE pairs for existing sections atomically; later-section/missing pairs display OUT; the initial enum contains only AVAILABLE/LOW/OUT, with no former-state conversion.

Fresh models remove EditorRef, per-record updatedBy, publication/connection creators, pending authors and History editors. Strict payload readers and ordered backup allowlists use the attribution-free initial v1 shapes. DeviceIdentity retains only operational identity/admin state/timestamps. Edit callbacks can receive guarded installation identity for PIN intent binding without recording it as authorship. Merge derived timestamps use operation time/ID ties. Existing development storage/files are rejected; no conversion is installed.

`DatabaseFactory` owns one shared connection with idempotent leases. Main repositories release leases; reset blocks acquisition, drains users and closes/reopens after cancelling the old observer. Staging uses separately owned one-shot connections closed before deletion. Restore/leave replace active rows transactionally rather than deleting the main database.

`ProtectedReadCache` caches decoded maintenance/compatibility metadata by secure-store namespace/entry under the shared read/write lock. Every write attempt invalidates its entry, even on failure; recovery clears metadata caches. Credentials/DB keys are excluded. Catalog observation reuses validated content on metadata-only invalidations, rereads after activation/leave and deduplicates equal states. Reader fallback decoding changes only with publication identity. Confirmed-state writers atomically persist exact ISO Instant publication text; restore validates it against the payload. The checked-in version-1 export has dated pre-attribution-removal evidence and is historical; [schema status](../app/schemas/README.md) records its pending regeneration.

## Import and protected connection state

SAF OpenDocument accepts broad MIME labels; authenticated envelope/domain/payload validation decides acceptance. ACTION_VIEW accepts content URIs matching connection MIME or `.aqz` JSON/octet-stream paths; opaque providers use the picker. File/http URIs are rejected, no persistable grant is taken and the memory-only URI is cleared from the intent to prevent recreation replay. External originals remain untouched; process death can require reselection.

The import repository uses a one-shot catalog read for unconfigured/non-demo/non-recovery eligibility before decoding and staging. It shares initialization, leave/restore completion, protected-state and integrity checks with observation without starting an invalidation flow. Configured devices use explicit same-pharmacy maintenance. One pending candidate is allowed, replaced only after confirmed discard. `pending-connection`/`active-connection` are separate from `database-key`; the versioned binary record carries magic, staging UUID, pharmacy/issuer metadata, token/group/key version and snapshot key. Modified-UTF text is capped at 8,192 UTF-16 units, record at 256 KiB, SecureStore at 1 MiB. Removal checks staging identity and writes an authenticated empty marker; corrupt/unsupported records fail closed.

Password UI uses unsaved `remember`; handoff clears text and transferred CharArrays are zeroed after completion/cancellation. ViewModel can retain URI/ongoing work across rotation, not unsubmitted passwords. UI exposes metadata only, never raw provider/crypto messages or credential URLs. Owned staging/key arrays are cleaned; immutable/provider copies cannot be claimed erased.

Load/stage/discard/verify/activate serialize in the repository; envelope/model work shares a process-wide mutex. Abandoned stages are cleaned on IO without delaying splash. Cancellation after an atomic write reloads actual protected state instead of claiming rollback; committed pending state needs explicit removal. Blocking providers/crypto may delay cancellation.

## Verification, requirements and activation

Pending verification checks staging ID, authenticates a fresh read and retains the candidate on failure/success. Its memory-only summary labels supported counts, publication identity/time, actual observation time and requirements (UTC before configuration); it does not authorize activation. Stable Arabic error categories replace raw transport/provider messages.

`SnapshotRequirementsStore` stores maximum authenticated schema/minVersionCode per pharmacy in protected 12-byte magic/schema/minimum-app records. Invalid authentication/pharmacy/caption/pin observations create no requirement. Records survive discard/re-import/restart, cannot be lowered or overwrite corruption, and finish persistence in a short noncancellable step; failed persistence returns recovery. Unsupported payloads never apply. Startup, refresh and commands enforce [compatibility restrictions](requirements.md#10-history-import-exports-updates), including retained restrictions on restore and authorized compatible backup export.

Activation downloads/authenticates again, checks candidate/requirements, writes protected active credentials then commits Room. The transaction accepts only the unconfigured seed with no pending/history/attempt/tombstone/base work; stores supported wire JSON plus publication/document/read metadata, retains installation identity, forces reader/shared lifecycle and imports no earlier history. Network remains cancellable; commit/cleanup complete noncancellably. Before commit, pending remains retryable; after commit, startup recognizes matching staging ID/pharmacy and finishes cleanup without network. Discard removes matching precommit credentials. Multi-instance invalidation updates observers; protected failures preserve data.

## Telegram reads and refresh

`SnapshotReadTransport` separates bot/pin/owned-download interfaces from official-host HTTPS getMe/getChat/getFile and credential-free fakes. It checks private group/supergroup identity, no public username, matching chat and a bot-owned non-forwarded document. Wire/header/caption/path/TLS/time/resource constraints remain in [readers](crypto/READERS.md).

Always-download reads authenticate pharmacy/key, compare caption/header and recheck full group/message/file/fileUnique/publication identity. Activation/publication/recovery always use this path. Refresh alone may skip download after strict reparsing of protected confirmed JSON and complete identity/pharmacy/key/compatibility equality; it uses the validated bot identity cached by token digest and rechecks the pin twice. Read 429 responses retain retry_after and enforce a monotonic per-token cooldown. Invalid cache fails closed; retained unsupported requirements force a fresh observation. This is no remote lock.

An app-owned Deferred coalesces foreground/pull/retry requests; a cancelled waiter does not cancel shared work. Navigation alone creates no request, local startup never waits for network and demo/unconfigured/draft/recovery paths create no foreground traffic. Automatic calls skip offline/admin/publishing work and successful reads under five minutes old; manual calls bypass the age gate and require an available network rather than Android validation and report applied/unchanged results. Completion/failure permits retry subject to cooldown; no permanent background worker exists.

Same-publication observations require semantic catalog/metadata equality independent of array order. A direct next revision requires the matching parent. The apply transaction also permits higher revision gaps on a clean catalog matching its confirmed base with zero pending operations/attempts. Strict lineage remains for local work; reused IDs, immediate-parent mismatches, divergence/regression, conflicts or uncertain attempts retain candidates for review. Application rechecks active identity, base metadata and visible catalog, then commits catalog/tombstones/base/document/read metadata and observed history atomically.

Only applied or unchanged accepted snapshots update the observed PIN and revoke mismatched authorization; rejected recovery candidates preserve authorization and device identity. Failures preserve usable data and times. Encrypted input is capped at 10 MiB, normalized JSON at 32 MiB; workspace checks precede history maps and never truncate.

Observed field JSON values carry revision/observation time, not invented original authorship. A separate publication event carries authenticated publisher/time. Recovery candidates use encrypted history `entityType=snapshot`, `field=recoveryCandidate`, oldValue=current base ID, newValue=complete supported wire JSON, deduplicated by base/candidate-derived UUID. They neither become pending attempts nor replace the base; backups retain them. Large history/snapshot/attempt values use bounded cursor/byte reads rather than assumed small rows.

## Creation, edits and publication

Current `local_control` stores lifecycle, PIN failure/observed/authorized verifier identities, reconnect intent, restore/reminder flags and resumable leave state. Protected `pin-delay` stores the shared promotion/current-PIN-change failure count, boot count and elapsed-time deadline; wall-clock changes do not bypass it. Process restarts preserve it; a reboot conservatively restarts the outstanding delay. Successful verification resets it, confirmed leave clears it, and backups never export it. Legacy wall-clock retry values are no longer used.

Creation atomically writes pharmacy/seeds/admin authorization; normalized salted PBKDF2-HMAC-SHA256/200,000 PINs are not retained. Accepted creation resets validation and a PIN-input session key, clears transferred secrets and uses collected/synchronous busy guards; failures restore untouched empty PIN inputs, invalid submissions retain entered text. Leave persists intent before protected/local cleanup, including the pharmacy-scoped selected-section preference; startup resumes it.

Admin transactions apply only changed catalog rows with inserts/updates/deletes ordered for foreign keys; ordinary edits do not replace the whole catalog. Catalog, history and saved-base operations commit together. Typed rows compare before JSON encoding, retaining each diff path’s field exclusions. Pending addition folding groups operations once and encodes only target rows. The injected clock timestamps creation and edits consistently. Explicit AdminProblem reasons cross the UI/publication/restore boundary; unexpected storage/platform details stay hidden.

Repeated edits retain original bases; unpublished additions absorb later changes, return-to-base removes net work without deleting history, and in-flight IDs are never coalesced away. Pending replay follows SQLite insertion order. Readers project confirmed data; promotion uses the latest observed verifier and durable increasing failure delays.

Separate setup/write adapters check official host, identity/group/admin permissions and setup-only random challenge discovery, refusing webhooks; manual group ID is validated and confirmed before protected setup credentials/key are saved. Writers use SecureRandom/domain-separated bounded encryption. Issuance requires verified shared state and SAF.

Publication serializes with setup/leave and persists candidate/base JSON, fixed operation IDs, upload IDs and phase before mutation. Shared state with no pending operations or uncertain attempt clears completed reconnect intent and returns without transport activity or claiming a verified publication. Retry cooldowns use elapsed time and expose remaining seconds as retryable status. Bootstrap uses revision 1/null parent/base 0 and refuses an existing pin; normal publication fetches/merges/rechecks the pin before media replacement, then always authenticates read-back.

The complete publication operation runs on IO under the existing sharing mutex, including protected reads, merge/JSON work and encryption between suspended transport calls. Snapshot-read NETWORK and RATE_LIMITED failures preserve retryability and an elapsed-time cooldown (including retry_after); other read failures stop automatic retries. The existing three-attempt reconnect bound, durable attempt identity and authenticated acknowledgement rules remain.

Pending-operation removal and history acknowledgment/retargeting chunk ID lists at 500 inside their transactions. Only exact verified candidates acknowledge captured work; later edits remain pending. Lost responses reconcile live identity; divergence/missing pins/ambiguous outcomes retain candidates for explicit review. Telegram offers no cross-device conditional write.

Merge compares business values, including deletion/dependent/reference/restoration conflicts. Normalized taxonomy-name collisions require an explicit surviving-item choice or a local rename; rejected category/form references use their fallbacks and rejected section availability is removed, as explained in review. A combined section count outside 1–5 requires choosing the retained local or remote section membership, preserving merged fields on surviving IDs.

Unrelated taxonomy changes survive. Deletion review compares only target/dependent business rows from both branches, including newly linked remote records. Its digest excludes unrelated rows and derived timestamps.

Old derived operations are not replayed over remote moves; fallbacks/cascades are recomputed from reviewed live state. Both local and remote tombstones are filtered against surviving merged entities, retaining history. If no local change survives, retain remote derived timestamps; otherwise select accepted changes by `(authoredAt, operationId)`, including derived reassignment.

This ordering never resolves conflicting business values. Online saves wait for Publish; retained offline intent may trigger up to three foreground reconnect attempts, paused by review/authorization/compatibility. Startup alone does not publish online-saved work.

## Encrypted backup and restore

`BackupRepository`'s authorized internal database-open/output-stream seams retain normal injection and all security/transaction guards. Under the sharing mutex, an ordered versioned table allowlist is captured in one Room transaction. `BackupArchive` encodes nullable cells as bounded Base64 UTF-8 chunks, preserving insertion order and large bases/history; active identity/authorization/reminders are excluded.

`V1BackupEnvelope` keeps the pinned 64 MiB complete-envelope domain. Private plaintext staging is immediately protected in independently authenticated 64 KiB AES-GCM chunks with an ephemeral key; import rows use separate SQLCipher storage. Conservative headroom covers provider buffering; OOM recovery is not a strategy. IO is off-main, serialized with crypto and cancellable between chunks, including queued input ownership. Export authenticates/validates staged output through the same payload path before SAF writing. Startup/next operation removes abandoned owned stages.

Authenticated UTF-8/type/reference-valid input materializes before active changes. Bounded copies replace allowlisted rows transactionally while retaining installation identity/revoking authorization. A protected write-ahead credential journal activates only for a matching committed Room checkpoint, replayed idempotently at startup. Restore pause, connection confirmation/activation and reminder state are current initial-schema fields, not an upgrade recipe.

Restored shared state pauses ordinary refresh/reconnect/publication until explicit group confirmation and live reconciliation. Same-bot tokens are validated without replaying transport phases; observed live verifiers revoke mismatched authorization, survive reconciliation/replacement and remove restored PIN-change intentions. Uncertain candidates are authenticated as accepted or explicitly archived before rebasing. Reconciliation never publishes; normal publish rechecks live PIN/lineage. Draft restore resumes through local/setup actions.

Reminder baseline is first local authorization, last fully closed successful SAF export and dismissal. An existing admin missing a timestamp gets a baseline on observation. These local values are excluded from backups, retained on same-pharmacy restore and cleared on leave. Resource/device measurements and their limitations belong in validation.

## Credential maintenance and recovery

`MaintenanceCoordinator` uses IO and the sharing mutex. Its bounded versioned SecureStore journal holds operation/phase, credential references, publication identities and backup receipts; original/candidate/temporary credentials remain separate protected entries. Isolated SQLCipher staging retains source catalog, bases, pending/attempt rows and candidate JSON using bounded large-value readers.

Preparation persists pause before capturing/resuming its stable baseline. Domain/refresh/reconnect guards enforce the pause; cached view, authorized backup/history/help and explicit recovery remain available. Corrupt metadata does not replace keys or erase work. Leave clears owned unreadable journal/staging entries; restore clears local maintenance/PIN associations, never importing their authority.

Activation writes a UUID to the protected journal, commits catalog/base and a matching Room history event, then switches active credentials only after that event is found. Startup completes activation before normal reads; interrupted precommit work keeps the old connection. Completion/cancellation cleanup is resumable; history projections hide internal checkpoints.

Replacement authenticates a bounded same-pharmacy `.aqz`, verifies fresh supported data, then downloads again and compares frozen local state before activation. Bases/uncertain attempts survive; readers retain confirmed-only projection. Admin review authenticates live state, recognizes exact accepted candidates or archives uncertain candidates, then reuses normal merge/timestamps. Invalid pending PIN intentions require explicit discard/new current-PIN authorization. Clearing pause does not schedule publication.

PIN creation/verification and connection-file passwords accept normalized numeric input of at least four digits; KDF/envelope bytes are unchanged. Issuance offers unsaved secure 16-digit generation/copy and inline guidance. Same-PIN changes stop before journal/pending creation. PIN changes bind current-PIN authorization, exact next verifier and operation ID in a protected local association. Only the installation's exact verified candidate/operation preserves its authorization, including lost-response reconciliation. Other verifier observations revoke it; no plaintext PIN or exported authorization is retained.

Maintenance backup reuses the mutex-owning export path; a receipt is issued only after complete validated writing/close. It binds operation/source publication/catalog/history/pending/attempt state. The UI warns to appoint one maintenance admin and pause other publications. Source changes invalidate it before irreversible progress; old exports/reminders do not qualify. Unavailable-source relocation requires digest-bound retained-publication/time review first.

Rotation authenticates the actual same bot/group with the old key before staging a new key/version. Relocation confirms a permission-checked empty destination. Both persist candidate identity/transport progress before mutation, publish source revision+1 with source parent/based-on lineage, authenticate new-key read-back and use recoverable activation. Resumption inspects destination before rewriting; unexpected publications/keys pause review. Issuance stays paused until completion. Cancellation after possible remote effects requires usable-state reconciliation, never a claimed remote undo; distribution/source retirement remain manual. Shared UI exposes identity/status/conflict summaries, not secrets or journal internals.

Normal publication rejects multiple stored attempts with a clear error. An explicit `recoverPin` command reuses the publication state machine and bypasses the empty-work early return only for a shared pharmacy. Missing pins or positively unrelated pins can enter retained-state review, bound to observed pin, retained catalog and attempt identity; damaged bot-owned documents/authentication/network failures cannot. A write-started uncertain candidate is reviewed and retained in recovery history before replacement. Pin rechecks/read-back and operation acknowledgment remain mandatory. A valid live snapshot uses ordinary publication. Explicit recovery now unpins the exact reviewed unrelated message after WRITE_STARTED, rechecks for remaining pins, then pins/verifies the candidate. Setup has a separate confirmed targeted-unpin action bound to the full inspected group/pin and draft/no-attempt guards. Neither path deletes messages or clears all pins; interruptions retain local work and may require fresh pin review.
