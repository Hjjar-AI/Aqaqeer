# Documentation ownership

- Keep one canonical home per concern: requirements = product rules/acceptance; architecture = implemented mechanisms; build = pinned commands/tooling; operations = recovery/admin procedures; Arabic guide = user actions; branding = artwork; crypto = exact wire/security contracts.
- Compact duplicated status/history and superseded proposals; never drop acceptance/security rules or move obsolete prose into an archive. Preserve canonical filenames and incoming anchors, or update every reference.
- Plan contains a short implemented baseline plus ordered IDs, priorities, dependencies, deliverables/completion criteria and remaining validation. Keep V1 separate; neither roadmap text nor documentation changes authorize implementation/execution.
- Validation contains current delivery/checkpoint, essential surviving evidence, one dated creation/sharing baseline and outstanding limits. Distinguish source work, compilation, executed results and human acceptance. Keep historical artifacts dated; do not present their results as validation of later changes.
- Keep durable working rules in AGENTS; environment-specific stops/approvals and remaining actions in plan; completed evidence/limits in validation; reusable commands/workarounds in build/operations. Update an existing checkpoint for minor changes rather than adding a section for every rename or warning fix; integrate appended updates into their topic instead of growing a chronological diary. Preserve deliberate reference/tutorial depth.
- Separate discovered/executed/passed/skipped/failed/interrupted outcomes and semantic scenarios from phase calls. Reconcile partial runs without discarding original evidence. Missing prerequisites/instrumentation are explicit limitations; lexical inventories are not measured declaration/branch coverage.
- Recovery records identify the exact boundary and mechanism, observed ownership/termination, cold verification and unavailable platforms. Controlled pressure, OS termination and power loss are distinct; assistant raster/semantics review is separate from human/spoken acceptance.
- Evidence links must survive authorized cleanup; ignored local evidence can be absent in fresh checkouts. Keep dates, source/artifact/device provenance and verified public hashes in the manifest. Never expose/hash credentials.
- Documentation checks are local link/anchor/integrity and whitespace checks. Builds, tests, lint, device and network actions require separate authorization; a stop remains in effect until the user resumes that activity.
